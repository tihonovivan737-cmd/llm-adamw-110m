# Обучение языковой модели 110M

Обучение с нуля на FineWeb-Edu с AdamW. Основной запуск рассчитан на Linux или WSL2 и две RTX 3090 по 24 ГБ. Веса чужой модели не используются: из TinyLlama загружается только готовый токенизатор.

## Конфигурация

| Параметр | Значение |
|---|---|
| Архитектура | Decoder-only Transformer, Llama-style |
| Обучаемые параметры | 109 529 856, округлённо 110 млн |
| Блоки / размер скрытого состояния | 12 / 768 |
| Attention | 12 голов, обычный multi-head attention, causal SDPA |
| FFN | SwiGLU, промежуточная размерность 2048 |
| Нормализация / позиции | Pre-RMSNorm / RoPE |
| Словарь / контекст | 32 000 / 1024 токена |
| Выходной слой | Общие веса с embedding |
| Bias / dropout | Нет / 0 |
| Данные | FineWeb-Edu, подвыборка sample-10BT |
| Бюджет | 300 000 000 обучающих целевых токенов, один проход |
| Валидация | Отдельные 2 000 000 целевых токенов |
| AdamW | LR 0.0006; betas 0.9, 0.95; eps 1e-8; weight decay 0.1 |
| Расписание LR | Разогрев 2% бюджета, затем cosine до 0.00006 |
| Global batch | 131 072 целевых токена |
| Microbatch | 2 последовательности на GPU |
| Накопление на двух GPU | 32 микрошагa на полный шаг AdamW |
| Точность | BF16 autocast; параметры и состояния AdamW FP32 |
| Ограничение нормы градиента | 1.0 |

Embedding и параметры нормализации исключены из weight decay. Всего 2289 шагов AdamW; последний неполный. Его loss нормируется по фактическому числу токенов, без повторения данных и без учёта padding. Две видеокарты работают через DDP: на каждой хранится копия модели, память не объединяется в один пул 48 ГБ.

300 млн токенов — стартовый бюджет для проверки оптимизатора, а не полноценное обучение конкурентоспособного чат-бота. FineWeb-Edu преимущественно англоязычный; этот запуск не ориентирован на русский язык. LR — исходная настройка, а не результат подбора на вашем оборудовании.

## 1. Установка

Нужны Python 3.10–3.12, NVIDIA-драйвер с поддержкой выбранной сборки CUDA и доступ к Hugging Face. Команды выполняются из каталога проекта в Linux/WSL2. В WSL2 проект и данные желательно держать в Linux-файловой системе.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install torch==2.7.1 --index-url https://download.pytorch.org/whl/cu128
python -m pip install -r requirements.txt
python -c "import torch; print(torch.__version__); print('GPU:', torch.cuda.device_count()); print('BF16:', torch.cuda.is_bf16_supported())"
```

Native Windows пригоден для однопроцессных проверок, но основной двухкарточный запуск использует NCCL и требует Linux/WSL2. Установка CUDA Toolkit отдельно не нужна для готового wheel PyTorch. Если драйвер старый, обновите его либо выберите совместимую сборку по официальной странице PyTorch.

## 2. Подготовка 300 млн токенов

```bash
python prepare_data.py --config configs/adamw_110m.json --output data/fineweb_edu_300m
```

Источник читается потоком. Не требуется скачивать всю подвыборку 10BT, но буфер перемешивания и чтение исходных файлов создают дополнительный трафик и кеш. Токенизированные train/val занимают примерно 604 МБ, не считая токенизатора и кеша Hugging Face. Предусмотрите дополнительно несколько ГБ свободного диска.

Версии источника и токенизатора закреплены commit hash в конфигурации. Документы распределяются между train и val по хешу до токенизации. Точные дубликаты отбрасываются; близкие по смыслу или частично совпадающие документы дополнительно не удаляются. Между документами добавляется EOS, блоки упаковываются плотно. Attention через границу документа разрешён. Последний документ может быть обрезан по бюджету.

В каждом файле хранится на один токен больше бюджета: это нужно для сдвига входа и целевого токена. Таким образом, обучение действительно использует ровно 300 000 000 предсказаний следующего токена. В manifest.json записаны размеры, SHA-256 и сведения об источнике. Токенизатор сохраняется рядом с данными.

Подготовка не перезаписывает существующие каталоги. При обрыве остаётся каталог с суффиксом .partial; автоматического продолжения подготовки нет. Для повторной попытки выберите другой путь или вручную удалите ненужный незавершённый каталог.

## 3. Проверка на двух GPU и основной запуск

Сначала короткий запуск той же полной модели:

```bash
python run_experiment.py --gpus 2 --output runs/adamw_seed42 --stop-after-steps 10
```

Он сохраняет latest.pt. Затем продолжите именно этот запуск до полного бюджета:

```bash
python run_experiment.py --gpus 2 --output runs/adamw_seed42 --resume
```

Либо сразу выполните подготовку и обучение одной командой:

```bash
python run_experiment.py --gpus 2 --prepare --output runs/adamw_seed42
```

Для независимого повторения:

```bash
python run_experiment.py --gpus 2 --seed 43 --output runs/adamw_seed43
```

Seed обучения меняет инициализацию модели, но не уже подготовленный корпус. Это позволяет сравнивать оптимизаторы на одинаковых токенах. Для честного сравнения сохраняйте архитектуру, токенизатор, данные, бюджет и global batch, а learning rate подбирайте для каждого оптимизатора отдельно. Одного seed недостаточно для надёжного вывода.

При нехватке памяти уменьшите micro_batch_size с 2 до 1 перед новым запуском: число микрошагов автоматически увеличится. Не меняйте global_batch_tokens, если хотите сохранить размер обновления. Опциональное ускорение компиляцией и сторонними attention-библиотеками не включено. Реальное потребление памяти и скорость нужно измерить на ваших GPU; оценка времени заранее не выдаётся за измерение.

## 4. Результаты, валидация и продолжение

Каталог запуска содержит config.json, data_manifest.json, копию токенизатора, metrics.jsonl и чекпойнты latest.pt / best.pt. Latest хранит последнюю сохранённую точку, best — лучшую среди проверенных обученных точек по validation loss. Сохраняются веса, AdamW, позиция в данных, шаг и состояния генераторов случайных чисел каждого процесса.

Чекпойнт одной полной модели с состояниями AdamW занимает около 1.3 ГБ; для двух чекпойнтов и временной записи оставьте хотя бы 5 ГБ. При аварии между сохранениями часть шагов придётся повторить. Для resume требуются прежняя конфигурация, тот же корпус и то же число процессов. Загружайте только доверенные .pt-файлы.

### Продолжение обучения с ещё 300 млн токенов

После базового запуска можно подготовить корпус на 600 млн обучающих токенов и продолжить из `latest.pt`. Сохраните каталог запуска: продолжение сверяет его исходный манифест и SHA-256 первых 300 млн токенов нового train-файла. Исходный каталог данных для этой проверки не нужен.

```bash
python prepare_data.py --config configs/adamw_110m_600m.json --output data/fineweb_edu_600m
python run_experiment.py --config configs/adamw_110m_600m.json --data data/fineweb_edu_600m --output runs/adamw_110m_seed42 --gpus 2 --resume --continue-training
```

Нужны `runs/adamw_110m_seed42/latest.pt`, исходный `runs/adamw_110m_seed42/data_manifest.json` и доступ к тому же закреплённому FineWeb-Edu. Второй этап продолжит шаги с позиции 300 млн токенов, сохранит состояние AdamW и использует постоянный learning rate `6e-5` — конечный уровень первого этапа. Проверки отклонят другой префикс данных, изменённую валидацию или несовместимую конфигурацию.

Во время обучения валидация выполняется каждые 100 шагов на фиксированных 262 144 токенах. Метрики: train loss, validation loss, perplexity, learning rate, норма градиента, скорость обучения и пиковая выделенная память GPU. Скорость не включает отдельную валидацию и запись чекпойнта. Окончательная оценка на всех 2 млн токенов:

```bash
python train.py --config configs/adamw_110m.json --data data/fineweb_edu_300m --resume runs/adamw_seed42/best.pt --eval-only --full-validation
```

Для запуска с другим seed передайте такой же --seed при отдельной оценке. Perplexity сравнима только при одинаковом токенизаторе и корпусе. Validation участвует в выборе чекпойнта; это не независимый test set.

## 5. Генерация

```bash
python generate.py --checkpoint runs/adamw_seed42/best.pt --prompt "The scientific method is" --max-new-tokens 100
```

Это продолжение текста, не диалоговая модель. Генератор простой, без KV-cache, поэтому он предназначен для проверки результатов, а не быстрого сервинга. Для CPU добавьте --device cpu.

## 6. Проверки и устройство проекта

```bash
python -m unittest discover -s tests -v
```

Тесты проверяют число параметров, causal attention, конечность градиентов, маскирование неполного батча, накопление градиентов, группы AdamW, расписание LR, упаковку токенов и восстановление обучения. Интеграционная проверка использует маленькую модель и синтетические данные; результаты непрерывного обучения и resume сравниваются побитово на CPU.

| Файл | Назначение |
|---|---|
| configs/adamw_110m.json | Архитектура, данные и гиперпараметры |
| prepare_data.py | Потоковое чтение, разбиение и токенизация |
| llm/model.py | Transformer и создание AdamW |
| llm/data.py | Чтение токенов и расписание LR |
| train.py | Обучение, DDP, оценка, сохранение и resume |
| run_experiment.py | Запуск эксперимента на одной или двух GPU |
| generate.py | Продолжение текста из чекпойнта |
| tests/test_training.py | Автоматические проверки |

Для подключения экспериментального оптимизатора точка замены — make_optimizer в llm/model.py. Предполагается стандартный интерфейс PyTorch optimizer: zero_grad, step, state_dict и load_state_dict.
